# Asteroids Demo

The editor's sample game: a small space game that shows how the engine's features fit together.
Open it with `task run` (it's the project the editor opens by default) and press **F5**.

**How to play:** from the menu, **Play**. Fly with the arrow keys or WASD, collect the glowing
stars, and dodge the bouncing rocks: each hit costs a life (with a moment of shields after it).
At zero lives your best score is saved and you're back at the menu. **Options** picks your ship
with Left / Right; the choice is saved too. While playing from the editor, **F9** shows the
physics shapes.

## What it demonstrates, and where

| Feature | Where to look |
|---|---|
| **Global scripts**: one instance for the whole game, across scenes | `scripts/game_state.odin` (score, lives, high score, chosen ship), `scripts/hud.odin`. Listed in **File > Project Settings > Globals**, which also sets their exported fields |
| **A global that draws** (over the scene, unmoved by the camera; it hides itself outside the play scene) | `scripts/hud.odin` (`draw`, `self.hidden`) |
| **Reaching a global** from any script | `e.Global(GameState)` in `pickup.odin`, `rock.odin`, `high_score_label.odin` |
| **Saving and loading** game state as JSON | `e.Load_Game()` in GameState's `ready`, `e.Save_Game()` at game over (`GameState_Hit`) and when picking a ship (`ship_picker.odin`). What's saved: fields that aren't exported, plus exported ones tagged `save:""` (the ship) |
| **Data types and data resources**: reusable data in files | `scripts/ship_stats.odin` (the type), `data/scout.data.json` and `data/hauler.data.json` (two ships). Select one in the browser's **Data** folder to edit it in the inspector; right-click the folder for **New Data Resource** |
| **Loading data** | `e.Data(ShipStats, ...)` in `player_ship.odin` and `ship_picker.odin`: the ship's speed, sprite, size and tint come from its data |
| **Typed asset handles from code** | `scripts/assets.odin` is generated by the editor: `SOUND_HIT`, `DATA_SCOUT`, ... (used in `rock.odin` via `GameState_Hit`, and `ship_picker.odin`) |
| **Asset handle fields** set in the inspector | `Pickup.sound` (an `e.SoundAsset`: a picker of the project's sounds), `PlayerShip.fallback` and `GameState.ship` (`e.DataAsset` with `kind=ShipStats`: only those resources are offered) |
| **Physics** | PlayScene: the player is a **CharacterMover** (`player_ship.odin`: `e.CharacterMover_Move`), the stars are **Areas** (`pickup.odin`: `collisionEnter`), the rocks **DynamicBodies** with bounce (`rock.odin`), the walls a **StaticBody** of segment shapes. The project has no gravity (Project Settings > Gravity 0) |
| **Input actions** | `player_ship.odin` flies with `e.Input_GetVector("ui_left", "ui_right", "ui_up", "ui_down")`: the project's ui_* actions (Project Settings > Input) map the arrow keys, WASD, a gamepad's d-pad and left stick |
| **Particles** | PlayScene: the player's **Exhaust** (a ParticleEmitter under it: a continuous stream that fades through the color ramp, left behind in the world as the ship moves), and **Sparks**, a one-shot burst (emitting and continuous off, burst 1) that `pickup.odin` moves to the star and fires with `e.ParticleEmitter_Start`. Select either to see every setting in the inspector |
| **Labels driven by scripts** | `high_score_label.odin` (menu), `ship_picker.odin` (options) |
| **Menus that switch scenes** | The menus in MenuScene and OptionsScene (no code) |

`scripts/mover.odin` and TestScene are an earlier experiment (a sprite that drifts right).

## Where saves go

- Played from the editor (`--dev`): your user data folder's `Asteroids Demo (dev)/saves/save.json`
  (on Linux `~/.local/share/Asteroids Demo (dev)/`), so testing never touches an exported game's saves.
- Exported for the desktop: `Asteroids Demo/saves/` in the same place; for the web: the browser's
  localStorage.

Delete the file to start over.
