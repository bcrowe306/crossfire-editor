# Asteroids Demo

The editor's sample game: a small space game, and a platformer level made in LDtk, that show how
the engine's features fit together. Open it with `task run` (it's the project the editor opens by
default; releases ship it beside the editor) and press **F5**.

**How to play:** from the menu, **Play**. Fly with the arrow keys or WASD, collect the glowing
stars, and dodge the bouncing rocks: each hit costs a life (with a moment of shields after it).
At zero lives your best score is saved and you're back at the menu. **Options** picks your ship
with Left / Right; the choice is saved too. While playing from the editor, **F9** shows the
physics shapes.

## What it demonstrates, and where

| Feature | Where to look |
|---|---|
| **Global scripts**: one instance for the whole game, across scenes | `scripts/game_state.odin` (score, lives, high score, chosen ship), `scripts/hud.odin`. Listed in **File > Project Settings > Globals**, which also sets their exported fields |
| **A global that draws** (over the scene, unmoved by the camera; it hides itself outside the play scene) | `scripts/hud.odin` (`draw`, `self.hidden`) |
| **Reaching a global** from any script | `e.Global(GameState)` in `pickup.odin`, `rock.odin`, `high_score_label.odin` |
| **Saving and loading** game state as JSON | `e.Load_Game()` in GameState's `ready`, `e.Save_Game()` at game over (`GameState_Hit`) and when picking a ship (`ship_picker.odin`). What's saved: fields that aren't exported, plus exported ones tagged `save:""` (the ship) |
| **Data types and data resources**: reusable data in files | `scripts/ship_stats.odin` (the type), `data/scout.data.json` and `data/hauler.data.json` (two ships). Select one in the browser's **Data** folder to edit it in the inspector; right-click the folder for **New Data Resource** |
| **Loading data** | `e.Data(ShipStats, ...)` in `player_ship.odin` and `ship_picker.odin`: the ship's speed, sprite, size and tint come from its data |
| **Typed asset handles from code** | `scripts/assets.odin` is generated by the editor: `SOUND_HIT`, `DATA_SCOUT`, ... (used in `rock.odin` via `GameState_Hit`, and `ship_picker.odin`) |
| **Asset handle fields** set in the inspector | `Pickup.sound` (an `e.SoundAsset`: a picker of the project's sounds), `PlayerShip.fallback` and `GameState.ship` (`e.DataAsset` with `kind=ShipStats`: only those resources are offered) |
| **Physics** | PlayScene: the player is a **CharacterMover** (`player_ship.odin`: `e.CharacterMover_Move`), the stars are **Areas** (`pickup.odin`: `collisionEnter`), the rocks **DynamicBodies** with bounce (`rock.odin`), the walls a **StaticBody** of segment shapes. The project has no gravity (Project Settings > Gravity 0) |
| **Components** | The stars are one component, `components/star.component.xml` (an Area with the `Pickup` script, its glow and its reach): PlayScene's Star1, Star2 and Star3 are instances of it, each with its own position. Double-click it in the browser's Components folder to change all three at once; an instance's **Make Unique** gives it a copy of its own |
| **Input actions** | `player_ship.odin` flies with `e.Input_GetVector("ui_left", "ui_right", "ui_up", "ui_down")`: the project's ui_* actions (Project Settings > Input) map the arrow keys, WASD, a gamepad's d-pad and left stick |
| **Particles** | PlayScene: the player's **Exhaust** (a ParticleEmitter under it: a continuous stream that fades through the color ramp, left behind in the world as the ship moves), and **Sparks**, a one-shot burst (emitting and continuous off, burst 1) that `pickup.odin` moves to the star and fires with `e.ParticleEmitter_Start`. Select either to see every setting in the inspector |
| **Labels driven by scripts** | `high_score_label.odin` (menu), `ship_picker.odin` (options) |
| **Menus that switch scenes** | The menus in MenuScene and OptionsScene (no code) |

## The forest level (LDtk)

From the menu, **Forest (LDtk)**: run with the arrows or A / D, jump with Space, W or Up (hold
it to jump higher), attack with J, X, the left mouse button or a gamepad's West button. Fight
snails, charging boars and diving bees (or stomp them), collect coins, take the key high up to
open the log blocking the way, and reach the chest. Touching an enemy or falling into a pit
costs health (the bar at the top); at none, the run ends. Escape goes back to the menu.

The level is `assets/forest/forest.ldtk`, an [LDtk](https://ldtk.io) project: open it with
**Open in LDtk** (the browser's Levels folder), change it, save, and a running game (Play)
updates its tiles and collision as you save.

| Feature | Where to look |
|---|---|
| **An LDtk level in a scene** | ForestScene's **Level** node (an LDtkLevel): the file, the level, and the IntGrid layer that becomes collision (`Collisions`) |
| **Auto-layer rules** | The `Collisions` IntGrid layer's rules in LDtk tile the ground: edges, corners, grass on top, planks. Paint ground in LDtk and it tiles itself |
| **Collision from an IntGrid layer** | The same layer's cells become one StaticBody of merged rectangles, which the hero stands on |
| **Parallax** | The `NearTrees` and `FarTrees` tile layers have parallax factors (0.3 and 0.6, set in LDtk): they move slower than the level as the camera follows the hero |
| **Entities as components** | The Level node maps each LDtk entity (Hero, Coin, Snail, Key, Gate, Chest) to a component in `components/`, which the game instances where the entity is |
| **Scripts named like entities** | `scripts/hero.odin`, `coin.odin`, `snail.odin`, `key.odin` (Key and Gate), `chest.odin`: attached because they're named like the entity, no setup |
| **LDtk fields set script fields** | The hero's `speed`, each coin's `value` (the one up high is worth 5), each snail's `patrol` (a Point: where it turns back) and `speed`: set per entity in LDtk |
| **Entity references** | The key's `opens` field points at the gate (an arrow in LDtk); `key.odin` finds the gate with `e.LDtk_EntityRefNode(self.node, "opens")` |
| **A platformer on a CharacterMover** | `hero.odin`: scripted gravity (the project has none), `e.CharacterMover_Move`, jump buffering and coyote time, short hops, a camera following inside the level's bounds (`e.Camera2D_SetBounds`, `e.Camera2D_Follow`), the sprite mirrored by a negative scale |
| **Removing nodes** | Coins, defeated enemies and the opened gate are removed with `e.Scene_RemoveNode` |
| **Combat** | `hero.odin`: the attack's two slashes hit what the sword reaches; `enemy.odin`: health, knockback (walkers never off a ledge: `e.LDtk_IntGridAtPosition` on the Collisions layer), a red flash, death animations, stomps and contact through physics (`e.PhysicsBody_IsInArea`); `snail.odin`, `boar.odin` (charges when it sees the hero), `bee.odin` (flies, dives) |
| **Hit feel** | `effects.odin`: blood (`components/blood.component.xml`, a one-shot ParticleEmitter instanced from code with `e.Scene_AddComponent`, its `Burst` script removing it with `e.Scene_RemoveComponent` when the emitter's `onFinished` event says it's done), a hitstop (`e.Game_HitStop`: the game freezes for a few frames) and a camera shake (`e.Camera2D_Shake`) |
| **A HUD for the level** | `hud.odin`: a health bar along the top (the lost part trails and drains), coins collected, score (enemies defeated and the chest) |

The art and sounds are from two asset packs (see `assets/forest/CREDITS.md`). The editor's
`tools/demo/make_forest.py` made the first version of the level from them.

`scripts/mover.odin` and TestScene are an earlier experiment (a sprite that drifts right).

## Where saves go

- Played from the editor (`--dev`): your user data folder's `Asteroids Demo (dev)/saves/save.json`
  (on Linux `~/.local/share/Asteroids Demo (dev)/`), so testing never touches an exported game's saves.
- Exported for the desktop: `Asteroids Demo/saves/` in the same place; for the web: the browser's
  localStorage.

Delete the file to start over.
